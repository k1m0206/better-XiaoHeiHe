评论/回复创建接口文档
该接口用于向帖子发布新评论或回复已有评论。

URL: https://api.xiaoheihe.cn/bbs/app/comment/create
Method: POST
Content-Type: application/x-www-form-urlencoded;charset=utf-8
1. 请求参数 (Request)
Query String Parameters (URL参数): 用于身份校验与环境识别。

| 参数名 | 类型 | 说明 | | :--- | :--- | :--- | | `heybox_id` | String | 当前登录用户的唯一 ID。 | | `hkey` | String | 请求安全加密摘要。 | | `nonce` | String | 随机字符串，配合签名校验。 | | `os_type` / `x_os_type` | String | 网页端环境标识，通常为 `web` / `Windows`。 | | `app` / `x_app` | String | 应用标识，网页端通常为 `heybox` / `heybox_website`。 | | `device_info` / `device_id` | String | 设备信息与设备 ID，发评论接口会随网页端环境参数一起提交。 |
Request Body (表单数据):

| 字段名 | 类型 | 必填 | 说明 | | :--- | :--- | :--- | :--- | | `is_cy` | Integer | 是 | 是否插眼评论，普通评论传 `0`。 | | `link_id` | Long | 是 | 关联的帖子或动态 ID。 | | `reply_id` | Long | 是 | 回复目标评论 ID；发布普通主评论时为 `-1`。 | | `root_id` | Long | 是 | 楼中楼根评论 ID；发布普通主评论时为 `-1`。 | | `text` | String | 是 | 评论/回复的具体文字内容。 |---
2. 响应数据结构 (Response Body)
| 路径 | 类型 | 说明 | | :--- | :--- | :--- | | `status` | String | 状态码，`ok` 为成功。 | | `commentid` | Long | 新生成的评论唯一识别 ID。 | | `result.comment.comment[0]` | Object | **评论详情对象**，用于前端回显。 | | `...user` | Object | 发送者信息（即你自己）。 | | `...replyuser` | Object | 被回复者信息（仅在 `replyid > 0` 时有效）。 | | `...ip_location` | String | 发送者的地理位置（如 `上海`）。 |---
3. 核心业务逻辑说明
回复类型判断：后端根据 `reply_id` 和 `root_id` 自动分流。普通主评论通常传 `reply_id=-1&root_id=-1`；回复评论时 `reply_id` 为目标评论 ID，`root_id` 为根评论 ID，无法确认根评论时可用目标评论 ID 作为兜底。
幂等性与安全：通过 nonce 和 hkey 防止接口被恶意重放（Replay Attack）。
即时性渲染：成功后返回的 result 包含完整的用户信息和勋章信息，前端应直接将其插入列表首位，无需重新刷新整个页面。

4. 网页端真实请求参考

以下样例来自网页登录态下的真实评论回复请求。Cookie 中的登录凭据已脱敏，调试时应使用当前浏览器实际 Cookie，不要复用文档中的占位值。

```bash
curl 'https://api.xiaoheihe.cn/bbs/app/comment/create?os_type=web&app=heybox&client_type=web&version=999.0.4&web_version=2.5&x_client_type=web&x_app=heybox_website&heybox_id=<heybox_id>&x_os_type=Windows&device_info=Chrome&device_id=<device_id>&hkey=<hkey>&_time=<timestamp>&nonce=<nonce>' \
  -H 'Accept-Language: zh,zh-CN;q=0.9' \
  -H 'Origin: https://www.xiaoheihe.cn' \
  -H 'Referer: https://www.xiaoheihe.cn/' \
  -H 'User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/150.0.0.0 Safari/537.36' \
  -H 'accept: application/json' \
  -H 'content-type: application/x-www-form-urlencoded;charset=utf-8' \
  -b 'user_pkey=<user_pkey>; user_heybox_id=<heybox_id>; heybox_id=<heybox_id>; x_xhh_tokenid=<x_xhh_tokenid>' \
  --data-raw 'is_cy=0&link_id=182351884&reply_id=877101178&root_id=877101178&text=%5Bcube_%E6%83%8A%E8%AE%B6%5D'
```

关键约定：

| 项 | 真实请求表现 |
| :--- | :--- |
| URL 环境参数 | `os_type=web`、`app=heybox`、`client_type=web`、`version=999.0.4`、`web_version=2.5`、`x_client_type=web`、`x_app=heybox_website`、`x_os_type=Windows`、`device_info=Chrome`。 |
| 设备参数 | 真实网页请求会带 `device_id`，示例值形如 `<device_id>`。 |
| 签名参数 | `hkey`、`_time`、`nonce` 每次请求动态生成，不能复用历史值。 |
| 登录态 | 依赖当前网页登录 Cookie，至少包含 `user_pkey`、`user_heybox_id`、`heybox_id`、`x_xhh_tokenid` 等登录相关字段。 |
| 请求体 | 回复评论时使用 `is_cy=0&link_id=<帖子ID>&reply_id=<目标评论ID>&root_id=<根评论ID>&text=<URL编码后的文本>`。 |
| 请求来源 | 网页端带 `Origin: https://www.xiaoheihe.cn` 和 `Referer: https://www.xiaoheihe.cn/`。 |

5. AI Bot 使用约定

AI Bot 在回复“@我”或“评论/回复我的”消息时，需要先解析到目标评论 ID；在评论首页推荐帖时，会发送普通主评论：

| 参数 | AI Bot 取值 |
| :--- | :--- |
| `is_cy` | 固定传 `0`。 |
| `link_id` | 消息关联的帖子 ID，或首页推荐帖的帖子 ID。 |
| `reply_id` | 回复消息时使用解析出的目标评论 ID，例如 `comment_a_id` / `comment_id`；首页推荐帖主评论固定传 `-1`。 |
| `root_id` | 回复消息时优先使用消息中的根评论 ID，例如 `root_comment_id`，缺失时使用 `reply_id` 兜底；首页推荐帖主评论固定传 `-1`。 |
| `text` | AI 根据帖子详情、评论区上下文和触发消息的评论或首页推荐帖内容生成的评论文本。发送前会去除代码块包裹和首尾引号，并限制最大长度。 |
| URL `heybox_id` / `hkey` / `nonce` / `device_id` | 使用当前浏览器中小黑盒网页登录态和后台签名逻辑生成，并补齐网页端环境参数。 |

AI Bot 内置全局评论冷却，同一浏览器中连续两次自动评论提交尝试间隔不少于 30 秒。冷却在发起 `comment/create` 前即写入本地运行状态，因此即使接口失败，下一条自动评论也会继续等待，避免失败重试过于频繁。接口成功返回 `status=ok` 后，AI Bot 才会把对应 `message_id` 标记为已回复；首页推荐帖主评论成功后会把 `link_id` 写入本地永久去重记录，之后不再重复评论该帖子。

AI Bot URL 参数复用策略：

- 用户打开小黑盒网页时，插件会从页面真实 API 请求 URL 中捕获 `os_type`、`app`、`client_type`、`version`、`web_version`、`x_client_type`、`x_app`、`heybox_id`、`x_os_type`、`device_info`、`device_id` 等非签名参数，并保存到浏览器本地存储。
- AI Bot 后台查询 @ 消息、查询帖子评论区和发送评论时，会优先复用这些真实参数；如果尚未捕获到真实 `device_id`，会记录提醒日志，提示打开一次小黑盒页面以完成缓存。
- `hkey`、`_time`、`nonce` 属于一次性签名参数，必须按当前接口路径和当前时间重新生成，不复用历史请求值。
- 插件不会把 `user_pkey`、`x_xhh_tokenid` 等 Cookie 登录凭据写入该参数缓存；登录态仍由浏览器 Cookie 机制随请求携带。
- AI Bot 发送评论前会临时为 `comment/create` POST 请求设置 `Origin: https://www.xiaoheihe.cn` 与 `Referer: https://www.xiaoheihe.cn/`，请求结束后立即移除该临时规则，以贴近网页登录页的真实请求来源。
