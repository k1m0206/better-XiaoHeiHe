1. 消息列表接口 (通用)
用于获取用户的各类消息通知，支持分类筛选。

URL: https://api.xiaoheihe.cn/bbs/app/user/message
Method: GET
Auth: 基于 Cookie
请求参数 (Query Parameters)
| 参数名 | 类型 | 说明 | 示例 | | :--- | :--- | :--- | :--- | | `message_type` | Integer | **关键参数**。消息类型：`16` 为“@我”，不传或特定值对应其他分类 | `16` | | `list_type` | Integer | 列表类型：`0` 通常表示“全部消息” | `0` | | `offset` | Integer | 分页偏移量 | `0` | | `limit` | Integer | 每页返回数量 | `20` | | `heybox_id` | String | 用户唯一标识 ID | `<heybox_id>` | | `os_type` | String | 操作系统类型 | `web` | | `hkey` / `nonce` | String | 安全校验与防重放参数 | - |
响应数据结构 (JSON)
| 路径 | 类型 | 说明 | | :--- | :--- | :--- | | `status` | String | 请求状态，`ok` 表示成功 | | `result.messages` | Array | 消息对象列表 | | `result.messages[].user_a` | Object | 发送者信息（头像、昵称、等级、勋章） | | `result.messages[].text` | String | 消息文本内容 | | `result.messages[].timestamp` | String | 消息生成的时间戳 | | `result.messages[].link` | Object | 关联的动态或文章详情（包含标题、图片、分享链接等） | | `result.messages[].link_tag` | Integer | 跳转类型标识，用于前端决定跳转页面 |---
2. 差异化说明
| 接口场景 | 核心参数配置 | 返回值特性 | | :--- | :--- | :--- | | **“@我”的消息** | `message_type=16` | `messages` 数组内仅包含 `@` 类型的通知，`text` 字段多包含 `@了我也`。 | | **评论/回复我的消息** | `list_type=0&offset=0&limit=20&no_more=false` | `messages` 数组为混合消息，AI Bot 会筛选 `message_type=1` 和 `message_type=2` 作为评论/回复类消息。 | | **所有消息** | `list_type=0` | `messages` 数组包含混合类型（点赞、评论、关注、系统通知等），`message_type` 字段值不固定。 |
小黑盒消息列表 API 响应结构
该接口返回标准的 JSON 格式，核心数据位于 result.messages 数组中。

1. 基础结构
| 字段 | 类型 | 说明 | | :--- | :--- | :--- | | `status` | String | 请求状态，`ok` 表示成功。 | | `version` | String | 接口版本号。 | | `result` | Object | 包含消息列表的主体对象。 |
2. 消息对象 (messages[]) 字段解析
| 字段 | 类型 | 说明 | | :--- | :--- | :--- | | `message_id` | Long | 消息的唯一 ID。 | | `message_type` | Int | 消息分类（如 `16` 代表被提及 @）。 | | `text` | String | 消息的描述文本（如 `@了我也`）。 | | `timestamp` | String | 消息产生的时间戳。 | | `user_a` | Object | **动作发起人**（如 @ 你的那个人）的信息。 | | `user_b` | Object | **动作接收人**（即你自己）的信息。 | | `state` | Int | 阅读状态（通常 `0` 为未读）。 | | `link` | Object | **关联内容实体**，指向具体的动态、评论或文章。 |
3. 用户对象 (user_a / user_b) 详情
| 字段 | 类型 | 说明 | | :--- | :--- | :--- | | `username` | String | 用户昵称。 | | `userid` | String | 用户唯一标识。 | | `avatar` | String | 用户头像 URL。 | | `level_info` | Object | 包含用户等级（`level`）和状态。 | | `medals` | Array | 用户佩戴的勋章列表（含认证信息 `is_auth_medal`）。 |
4. 关联实体 (link) 详情
| 字段 | 类型 | 说明 | | :--- | :--- | :--- | | `linkid` | Long | 关联内容的 ID。 | | `link_tag` | Int | 内容类型标识（如 `21` 可能代表转发动态）。 | | `title` | String | 关联内容的标题。 | | `description` | String | 关联内容的简短描述或正文片段。 | | `share_url` | String | 该内容的 H5 分享链接。 | | `forward` | Object | 若为转发消息，此处包含原帖的详细信息。 |

4. AI Bot 使用约定

AI Bot 后台可按设置分别查询“@我”和“评论/回复我的”消息：

- 回复 @ 开启时，使用 `message_type=16` 查询“@我”消息。
- 回复评论开启时，使用 `list_type=0&offset=0&limit=20&no_more=false` 查询全部消息，并筛选 `message_type=1` / `message_type=2`。

AI Bot 会读取以下字段：

| 字段 | 用途 |
| :--- | :--- |
| `message_id` | 作为已回复记录的幂等键，成功回复后写入本地，避免重复回复。 |
| `user_a.userid` / `user_a.heybox_id` 等 | 作为 @ 发起用户 ID，用于匹配 AI Bot 白名单。 |
| `link.linkid` / `link.link_id` | 作为帖子 ID，用于继续查询帖子详情和评论区。 |
| `comment_a_id` / `comment_id` / `commentid` / `replyid` / `reply_id` 等评论 ID 字段 | 优先作为回复目标评论 ID；`comment_a_id` 表示动作发起用户 @ 我的那条评论。 |
| `root_id` / `root_comment_id` / `rootCommentId` 等根评论 ID 字段 | 作为楼中楼根评论 ID；若消息只返回根评论 ID，则 AI Bot 会把根评论 ID 作为回复目标兜底。 |
| `comment_a_text` | 评论/回复消息中，动作发起用户发送的评论文本，会作为 AI 回复上下文。 |
| `comment_b_id` / `comment_b_text` | 评论/回复消息中，被回复的上一条评论 ID 和文本，会作为 AI 回复上下文。 |

AI Bot 拒绝回复关键词规则：

- 使用 `comment_a_text`，并依次以 `comment_text`、`content`、`text` 作为兜底，提取当前触发评论或回复的文本。
- 文本命中自动回复设置中的任一拒绝回复关键词时，会把该 `message_id` 标记为已跳过，不再查询帖子详情、生成 AI 内容或发送回复。
- 队列发送前会使用最新设置再次检查，确保新增关键词也能阻止已经入队但尚未处理的消息。

AI Bot 新鲜度规则：

- 默认只处理最近 5 分钟内的 @、评论和回复消息，可在设置中调整。
- 消息时间使用 `timestamp` 字段，支持秒级整数、小数秒和毫秒级时间戳。
- 超过时间窗口的旧消息会被写入本地已处理记录，后续轮询不再回复，避免开启 AI Bot 后补回历史消息。

如果接口返回登录失效、未授权或非 `ok` 状态，AI Bot 会记录日志；登录失效时会通知用户并自动关闭开关。
